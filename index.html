02 / Where the builds come from

Real manuals.
Controlled challenges.

We recommend both. Start with simple builds in each source, grow their difficulty together, and keep the results separate.

REAL SETS

Test the skill we care about.

Actual manuals bring real page layouts, subtle part differences, camera changes, and subassembly callouts. They tell us whether the system works beyond our generator.

  • Begin with small sets and short, clear manuals.
  • Verify every reference against the exact set and instructions.
  • Record public-data exposure and ambiguous placements.

Does it transfer to a real instruction book?

GENERATED BUILDS

Find out why it fails.

Original builds let us isolate a rotation, offset, quantity, or hidden connection. Fresh design families add challenges beyond familiar public sets.

  • Change one factor at a time in matched tasks.
  • Validate labels independently of the generator.
  • Hold out templates and families, not only random seeds.

Which change breaks the model?

⇄

The bridge between them: a paired transfer panel. Show the same held-out build through real and generated instructions. Compare whole-build outcomes; compare individual steps only when the states and operations align.

04 / What counts as success

The right pieces.
In the right places.

The main result is exact whole-build completion. Inventory, physical validity, instruction fidelity, and presentation remain separate dimensions.

01

Measure the whole object.

One-to-one part matching, correct colors, symmetry-aware poses, and no extra or missing pieces. Report tolerant scores separately from exact completion.

02

Keep the model’s mistakes.

Whole-build runs carry predicted state forward. No correct-prefix resets. Record the first error, later repairs, and whether the system actually finishes.

03

Make unknowns visible.

Connections, collisions, support, and insertion each get pass, fail, or unknown. Physical verification includes its coverage; an unsupported check is not a pass.

04

Declare the assistance.

Separate model-only and tool-assisted runs. Log rendering, code, legal candidates, snapping, retries, tokens, elapsed time, and cost.

Test the test.

Before model baselines, the scorer must reject duplicate-all answers, missing pieces, half-stud errors, wrong asymmetric rotations, and illegal connections. Real symmetries and equivalent instance orderings must pass.

05 / The first release

Small enough to verify.
Varied enough to learn.

A pilot concentrated in Foundations and Small Builds. Every number below is a proposed target, subject to reference verification.

12 + 12real + generated builds
240diagnostic step tasks
60repair cases, including 20 clean controls
  1. FirstFreeze the protocol.

    Define inputs, budgets, splits, equivalences, and scorer regression cases.

  2. ThenVerify the pilot.

    Curate builds, align instructions, annotate evidence, and independently check references.

  3. NextRun the baselines.

    Compare oracle candidates, random legal picks, a zero-shot model, and its tool-assisted version.

  4. AfterGrow the challenge.

    Expand independent families, publish replayable failures, then add longer builds and mechanisms.

The pilot validates the method. It is too small for confident fine-grained model rankings.

06 / Comparing different models

One test.
Many model adapters.

Every model receives the same task contract. A small adapter handles its API; a shared controller manages the build; an independent evaluator scores the saved result.

Frozen task packet→Model adapter→Actions & assembly→Independent scorer

Compare fairly.

Pin model versions, prompts, images, budgets, and retry rules. Separate model-only runs from agents using the same renderer, candidates, and validator. Report success alongside cost and time.

Run once. Rescore later.

Save raw responses, actions, tool traces, and final predictions. Resume interrupted cases. When a scorer changes, reevaluate the saved outputs without paying for inference again.

Run and compare models ↗

Development CLI available: OpenAI and Anthropic adapters, saved predictions, offline scoring. API adapters are locally tested; no paid model results yet.
